## 摘要
虚拟细胞正从单任务预测模型演变为可编程的生物模拟系统，但异质数据、模型与验证证据仍缺乏统一的组织框架。在此，我们提出 PRAXIS-VirtualCell，一个模块化框架，用于组织生物数据、预测模型、扰动、适配器、执行环境与验证证据，从而实现可重复且可审计的虚拟实验。该系统支持跨越大肠杆菌、酿酒酵母和人K562细胞的跨物种任务，并利用生物契约与证据感知执行来区分有支持的预测与外推和弃权。通过进一步集成智能体编排，PRAXIS-VirtualCell 可自动将自然语言问题转化为可追溯的虚拟实验，为可信且可扩展的虚拟细胞系统提供统一的运行时基础。

## Abstract
Virtual cells are evolving from single-task predictive models toward programmable biological simulation systems, yet heterogeneous data, models, and validation evidence still lack a unified organizational framework. Here, we present PRAXIS-VirtualCell, a modular framework that organizes biological data, predictive models, perturbations, adapters, execution environments, and validation evidence to enable reproducible and auditable virtual experiments. The system supports cross-species tasks spanning Escherichia coli, Saccharomyces cerevisiae, and human K562 cells, while using biological contracts and evidence-aware execution to distinguish supported predictions from extrapolation and abstention. By further integrating agentic orchestration, PRAXIS-VirtualCell automatically translates natural-language questions into traceable virtual experiments, providing a unified runtime foundation for trustworthy and scalable Virtual Cell systems.

## 1. 核心问题与整体含义（研究动机与背景）

- **虚拟细胞的范式转变**：虚拟细胞研究正从"显式重建全部细胞机制"（如 Karr 等人的支原体全细胞模型）转向"直接从数据学习细胞状态与扰动响应"（如 Geneformer、scGPT、GEARS 等）。
- **关键瓶颈**：一旦虚拟细胞从单模型扩展为多模型、多数据集、多任务系统，就出现新的基础性问题——**如何将异构生物数据与计算模型组合成显式、可复现、且受生物学意义约束的虚拟实验？**
- **现有评估的局限**：当前评测主要聚焦预测性能，而跨数据集、跨条件、跨物种泛化、训练数据污染、任务覆盖度、结果校准等维度日益重要；更重要的是，一个高性能单任务预测器 ≠ 一个能可靠执行开放式虚拟实验的虚拟细胞。
- **弃权（abstention）的科学地位**：真实虚拟实验必然遇到训练分布之外的基因、状态、条件与扰动组合。当无合适模型、输入不兼容或缺乏验证证据时，强行输出数值预测会掩盖模型真实边界。因此"**能否在给定数据、模型与证据下可靠预测**"应先于"预测结果是什么"。
- **论文定位**：提出 PRAXIS-VirtualCell，把虚拟细胞重新定义为**可编程的模块化运行时系统**，而非单一通用预测模型，目标是从孤立预测模型走向可扩展、可审计、可编程的虚拟细胞系统。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
- 将虚拟实验分解为**七个可独立配置的组件**：生物数据、细胞状态、扰动、预测模型、适配器（adapter）、执行环境、验证证据。
- 模型作为"可替换模块"，通过共享运行时组合，把固定预测流水线转变为可编程生物实验系统。

### 2.2 关键组件与机制

- **VirtualCellPack（数据契约）**：记录物种/细胞身份、实验条件、特征空间、扰动类型、对照、组学信息与数据溯源，实现数据与模型解耦。
- **模型契约（Model Contract）**：模型独立声明其支持的物种、输入、扰动、输出、所需适配器、执行环境与验证范围。
- **适配器与执行环境独立管理**：适配器负责标识符映射、特征对齐、预处理、扰动编码与输出转换；软件版本、参数、计算环境单独记录，使执行可追溯到"数据+模型+适配器+环境"的特定组合。
- **虚拟实验的显式表示**：每个查询被表示为显式虚拟实验——定义状态与扰动 → 兼容性检查（生物身份、特征空间、扰动、读出、适配器、执行环境）→ 执行 → 记录预测及其完整实验上下文。
- **证据感知执行（Evidence-aware Execution）**：验证证据与模型可执行性分离。证据分四类：开发验证（development validation）、外部压力测试（external stress testing）、技术可复现性（technical reproducibility）、科学验证（scientific validation）。技术可复现性≠生物学有效性；科学验证状态不能由任何单次执行或基准结果自动升级。
- **弃权机制**：当野生型模型不可行、扰动超出声明范围、无法建立特征空间映射或缺少执行组件时，实验被记录为 unsupported/abstained，并排除出主要性能汇总。

### 2.3 智能体编排（Agentic Orchestration）
- **五阶段流程**：Ask → Review → Route → Run → Results。
  - **Ask**：自然语言问题转为结构化实验请求。
  - **Review**：暴露解析出的生物上下文与预测目标供兼容性分析。
  - **Route**：识别合适的 VirtualCellPack、模型与适配器，生成候选执行方案。
  - **Run**：编译为确定性虚拟实验 DAG，由注册预测器执行。
  - **Results**：输出结构化虚拟实验记录。
- **权限边界**：语言模型只能协助解析、规划与文本解释；**不能创建数据、修改特征映射、生成模型输出、签发验证证据或覆盖执行决策**。数值输出只能来自注册预测器。
- **输出记录**：每次 Agent Run 产生报告、预测/弃权、模块路由、执行身份、证据、执行轨迹与溯源等互联记录。

## 6. 主要结论与发现

- **架构层面**：虚拟细胞的通用性不来自通用预测器，而来自能组织异构状态、专用模型与验证证据的共享运行时，同时保留清晰的任务边界与执行身份。
- **跨物种可行性**：同一运行时无需修改核心架构即可支持大肠杆菌、酵母与人类 K562 三类异质任务。
- **模型能力 vs 系统能力分离**：软件可执行性不等于科学支持；系统应能判断"是否应该预测"，而非仅"如何预测"。
- **证据分层有效**：开发验证、外部压力测试、技术可复现性与科学验证作为独立证据状态存储，弃权成为与预测同等重要的科学结果。
- **智能体边界清晰**：LLM 负责问题解析、模型路由与结果解释，兼容性判断、模型执行、证据评估与执行裁决由确定性运行时控制，可避免语言模型"幻觉预测"。
- **可追溯与可复现**：数据版本、适配器、特征映射、软件环境与实验条件被记录为执行身份的一部分。
- **未来愿景**：虚拟细胞将演化为由模型、数据、状态、智能体与验证组成的持续演化科学平台，而非单一固定神经网络。

## 7. 优点（方法与实验设计亮点）

- **架构解耦彻底**：数据、模型、适配器、执行环境、验证证据五大组件独立管理，新数据/模型/证据可增量扩展而不重建系统。
- **生物契约显式化**：通过 VirtualCellPack + 模型契约 + 适配器，把"能否回答同一生物学问题"从软件层面提升到科学语义层面。
- **证据感知执行**：将验证证据与执行状态分离，是区别于传统 MLOps 的关键创新，使弃权成为一等公民。
- **智能体权限边界设计**：LLM 与确定性运行时职责清晰分离，防止语言模型生成替代性数值预测或覆盖兼容性失败。
- **端到端可审计**：每次 Agent Run 记录报告、预测/弃权、模块路由、执行身份、证据、轨迹与溯源，满足 FAIR 原则与 model card/datasheet 规范。
- **诚实的失败记录**：明确标注不支持条件（蔗糖、极低葡萄糖）、跨菌株压力测试（BW25113 vs MG1655）、多菌株聚合（S288C/Y55/YPS/UWOP）等，避免过度宣称。
- **外部验证严谨**：锁定特征映射顺序、禁止缺失特征插补、模型选择不使用外部数据集，降低数据泄漏。

## 9. 对领域的启示与未来方向

- **从"模型竞赛"转向"系统竞赛"**：论文隐含地批评了当前虚拟细胞领域以单一预测器 SOTA 为核心的评估文化。它提示社区，随着模型与数据日益异构，**运行时的组织能力、契约的严谨性与证据的可审计性**可能比再提升几个百分点相关性更重要。
- **弃权应成为标准报告项**：如同分类任务报告精度需同时报告覆盖率，虚拟细胞实验应同时报告"预测率 / 弃权率"及其原因分布。论文把弃权从"失败"重新定义为"科学上诚实且必要的一等输出"，这对临床与药物发现等高风险场景尤为关键。
- **验证证据的层级化治理**：将开发验证、外部压力测试、技术可复现性、科学验证分列为独立状态，为"模型能力声明"提供了可操作的元数据范式，可推广至基础模型卡（model card）与数据表（datasheet）实践。
- **智能体与确定性内核的分工范式**：LLM 仅做解析、规划与解释，数值与裁决交给确定性运行时，这一"窄智能体 + 强内核"架构，为生物医学智能体系统的安全设计提供了可借鉴模板。
- **明确的未来工作清单**：作者提出不确定性量化、持久化细胞状态、实验反馈闭环（预测—湿实验—再训练）、更丰富证据类型与跨物种迁移契约等方向，指向"持续演化的科学平台"而非静态模型。

## 10. 总体评价与定位

- **贡献性质**：PRAXIS-VirtualCell 是一项**系统性 / 架构性贡献**，而非预测性能突破。其价值在于提出了一套可操作的概念框架与工程实现，把"虚拟细胞"从模型层面提升到"可编程实验运行时"层面。
- **最强论点**：虚拟细胞的通用性来自共享运行时与显式生物契约，而非通用预测器；证据感知执行使系统能够回答"是否应当预测"这一先于预测本身的问题。
- **最弱环节**：实证支撑与其宏大框架之间存在张力。跨物种验证的样本量小、统计功效弱、缺乏消融、且预测精度并不突出（K562 上简单加性模型即优于 GEARS），使得"运行时优于单模型"的论断目前更多是**架构论证**而非**实证结论**。
- **可信度评估**：论文在诚实性上表现突出——主动披露不支持条件、跨菌株压力测试、元数据冲突与负面结果，降低了过度宣称风险；但也正因如此，其结论应被理解为"可行性演示（feasibility demonstration）"而非"有效性证明（efficacy proof）"。
- **适用场景**：适合作为多模型、多数据集虚拟细胞平台的组织蓝图与治理规范参考，尤其适用于需要审计、复现与责任边界的科研协作或监管敏感场景；不适合期待即插即用高精度预测的用户。
- **一句话总结**：PRAXIS-VirtualCell 把虚拟细胞重新定义为**受证据约束、可弃权、可审计的可编程实验系统**，在架构与治理层面贡献显著，但在预测效能与统计严谨性上仍需后续实证补强。
