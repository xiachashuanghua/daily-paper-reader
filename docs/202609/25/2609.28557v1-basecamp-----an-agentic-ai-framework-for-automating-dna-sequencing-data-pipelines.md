## 摘要
DNA 测序流水线涵盖质量控制、比对、变异检测和注释，如今已可由工作流管理系统可靠执行，这些系统能够大规模编排成熟的生物信息学工具。仍然依赖人工的是围绕该执行的决策层：选择适合样本和平台的质量阈值，裁定临界变异检出，诊断异常，并确定哪些发现值得专家复核。这些决策重复性强、依赖判断、在不同操作者之间不一致，且常常缺乏记录。本文介绍 BaseCamp，一个用于自动化 DNA 测序流水线决策层的新型代理式 AI 框架。该框架将流水线分解为六个专门的 AI 智能体，分别覆盖样本接收与质量控制、比对、变异检测、注释、跨阶段监测和报告。关键的是，BaseCamp 智能体并不执行序列分析：成熟的工具执行比对、检测和注释，而智能体则在这些工具之间进行选择、配置它们、解释其输出，并决定后续步骤。这将语言模型推理限制在其可靠的判断层，并保留了现有工具所保证的可重复性。智能体的推理由一个经过微调、领域专用的大语言模型联盟驱动，并由一个中心推理 LLM 协调；这些模型在本地执行，因此没有测序数据离开运行环境，同时处于人在回路编排之下。评估表明，智能体生成的配置与专家实践一致；显式的过滤台账使原本会被过滤而无痕移除的内容变得可检查；跨阶段异常检测能够揭示执行监测遗漏的情况。BaseCamp 为科学数据流水线的代理式自动化提供了一个可推广的蓝图。

## Abstract
DNA sequencing pipelines, spanning quality control, alignment, variant calling, and annotation, are now reliably executed by workflow management systems that orchestrate established bioinformatics tools at scale. What remains manual is the decision layer surrounding that execution: selecting quality thresholds appropriate to a sample and platform, adjudicating borderline variant calls, diagnosing anomalies, and determining which findings warrant expert review. These decisions are repetitive, judgment-intensive, inconsistent across operators, and frequently undocumented. This paper introduces BaseCamp, a novel agentic AI framework for automating the decision layer of DNA sequencing pipelines. The framework decomposes the pipeline into six specialized AI agents, covering sample intake and quality control, alignment, variant calling, annotation, cross-stage monitoring, and reporting. Critically, BaseCamp agents do not perform sequence analysis: established tools execute alignment, calling, and annotation, while the agents select among them, configure them, interpret their output, and decide what follows. This confines language model reasoning to the judgment layer where it is reliable and preserves the reproducibility existing tooling guarantees. Agent reasoning is powered by a consortium of fine-tuned, domain-specialized large language models coordinated by a central reasoning LLM, executing locally so no sequencing data leaves the operating environment, under human-in-the-loop orchestration. Evaluation shows agent-generated configurations are concordant with expert practice, that an explicit filtering ledger renders inspectable what filtering otherwise removes without trace, and that cross-stage anomaly detection surfaces conditions execution monitoring misses. BaseCamp offers a generalizable blueprint for agentic automation of scientific data pipelines.

## 1. 核心问题与研究动机

- **背景**：DNA 测序流程（原始读段质控 → 修剪 → 参考比对 → 去重 → 变异检测 → 过滤 → 功能注释）的**执行层**已高度自动化，Nextflow、Snakemake、Galaxy、nf-core 等可在大规模样本上可重复地编排 FastQC、BWA、GATK、VEP 等成熟工具，并保证 provenance。
- **缺口**：仍依赖人工的是围绕执行的**决策层**——为特定样本/平台选择质量阈值、解读 QC 报告、裁定边界变异、诊断异常、判断哪些结果需要专家复核。这些决策重复性强、判断密集、跨操作者不一致、且往往不留记录。
- **具体痛点**：
  - 过滤决策是**沉默的**（被过滤的变异下游不可见）且**累积的**（后续分析全部继承，无从追溯理由）。
  - 工作流管理器能发现"作业崩溃"（执行失败），但**无法发现"每步都成功、结果却是错的"分析型异常**；异常通常在结果被使用后才被回溯发现。
- **已有 LLM 工作的错位**：基因组语言模型（DNABERT、HyenaDNA）作用于核苷酸序列；GeneGPT/BioMANIA/AutoBA/CellAgent 面向**下游分析**（差异表达、单细胞注释等），而非产生数据的上游生产流程；且多依赖外部 API 前沿模型，无领域微调、无本地执行，不符合数据合规要求，也缺少人工审批门与推理留痕。
- **总体含义**：BaseCamp 主张把 LLM 推理**限制在判断层**，让成熟工具继续负责计算，从而在获得自动化收益的同时保留可重复性与可审计性，并为科学数据管线的智能体化提供**领域无关的通用蓝图**。

## 2. 方法论

### 2.1 核心思想
- **"工具计算，智能体决策"**：智能体不执行序列分析，只负责选择工具、配置参数、解释输出、决定后续动作、判断何者需人工介入。这一分工是**承重设计**：既把 LLM 限制在其可靠的判断层，又保证结果来自经独立验证的工具而非语言模型生成。

### 2.2 六智能体分解（对应手工流程的认知职责）
| 智能体 | 职责要点 | 通过 MCP 连接的工具 |
|---|---|---|
| A1 样本接收与 QC | 联合解读指标轮廓、文库类型、平台、批次位置；输出修剪参数+理由、pass/review/fail 处置、批次离群样本识别 | FastQC、MultiQC、fastp |
| A2 比对 | 参考基因组/比对器选择（非模式生物尤为关键）；**联合解读**映射率、properly paired、插入片段分布、覆盖均匀度、重复率，区分文库制备问题/污染/参考分歧等特征性故障签名 | BWA、Bowtie2、SAMtools、参考库、LIMS |
| A3 变异检测 | 依深度/平台/倍性/胚系-体细胞选择 caller；过滤阈值需说明敏感性-特异性权衡；**输出过滤台账**；边界调用逐条标记 | GATK、DeepVariant、bcftools |
| A4 注释与解读 | 在 VEP/SnpEff/ANNOVAR + gnomAD/dbSNP 富集基础上做**优先级筛选**（后果严重度、人群频率、兴趣区域、遗传模式、研究目标），记录筛选逻辑；在育种场景做基因型-表型跨源关联 | VEP、SnpEff、ANNOVAR、gnomAD、dbSNP、表型库 |
| A5 跨阶段监控与异常 | 持续观测全阶段，检测**跨阶段联合不合理**（单阶段均合格）、覆盖不足、污染/索引跳变、检出率异常、批次效应、停滞/失败；输出按紧迫度排序、附指标证据与候选诊断的告警 | 全阶段指标 + 历史可比批次分布 |
| A6 报告 | 组装优先变异集、逐阶段推理链、过滤台账、待裁定项、完整运行配置（工具版本/参数/模型版本/适配器修订）；面向不同受众生成报告 | 运行配置记录 |

### 2.3 协调与编排
- 每个工作流暴露为**独立 MCP 服务器**，生物信息学家通过 LM Studio 的统一自然语言界面同时编排六个智能体。
- 服务器可单独寻址 → **争议单一阶段可只重跑该阶段**，无需重算整条管线（全流程重跑以小时/天计）。
- 智能体间通过**结构化中间输出**传递状态，下游获得完整上游上下文（手工交接恰恰丢失推理过程）。
- 人工审批门（H）嵌入关键转换点：QC 处置、比对配置、过滤阈值、边界变异裁定、异常分级、报告发布。

### 2.4 LLM 联盟 + 中心推理 LLM
- 单一智能体的提示被分发到多个**领域微调**模型（Llama-3、Mistral、Qwen 2.5，各配不同功能适配器），各自给出"建议 + 引用指标 + 置信度"。
- **中心推理 LLM（OpenAI GPT-OSS）** 识别一致、隔离分歧、核验各模型引用指标，产出合并决策。
- **关键规则**：模型间未解决的分歧**记录并上报人工**，而非取平均抹平——分歧本身就是该决策值得人工判断的信号。

### 2.5 微调流程
- 语料：历史 QC 报告+处置、管线日志+参数、过滤决策+理由、生物信息学家复核笔记；按 80/10/10 切分。
- 基座模型（4-bit）→ Unsloth + LoRA + QLoRA → **每个分析功能一个适配器（共 4 个）**，单基座常驻显存、随管线推进**热切换适配器**。
- 离线微调，部署时模型行为固定 → 同一样本两次运行可对账。Ollama 本地服务，**无外部 API 依赖、无测序数据出域**。

### 2.6 负责任与可解释 AI 的四重机制
1. 联盟式多视角验证，降低单模型偏见/幻觉；
2. 每个输出附**显式推理链**（引用具体指标与阈值、参数理由、过滤影响调用数）；
3. 关键转换处**人工审批门**；
4. **完整运行配置随输出记录**，保证可复现/可重算。

### 2.7 提示约束（A3 为例，规则可视为"算法契约"）
- 每条决策必须引用具体指标——"**无指标，不决策**"；
- 上游上下文不足以支撑阈值时输出 `INSUFFICIENT CONTEXT` 并上报，**不得静默回退默认值**；
- 永不在缺少台账的情况下报告过滤后的调用集；
- 输出结构化 JSON + 人类可读摘要。
