## 摘要
智能体式生物医学机器学习（ML）借鉴了生物医学证据获取与可执行程序搜索方面的互补进展。现有系统连接了这些能力的若干方面，但在整个程序搜索过程中协调它们仍具挑战性。新证据必须指导候选构建，执行结果必须为后续发现与复用提供信息，验证需求必须适配搜索预算。我们提出 BioDyad，它通过蒙特卡洛图搜索中的两个层级，将生物医学发现与 ML 工程耦合起来。其科学层级将先验生物医学指导与迭代发现相结合，随后在记忆中把生物医学方案与执行结果关联起来，以便在不同候选之间复用。其工程层级推动候选程序从冒烟执行，经过训练/验证评估，再到全数据重训练。我们在每个任务两小时预算下，使用三个匹配的 LLM 后端，在包含 76 个任务的 BioXArena 基准上评估 BioDyad。在每个后端下，它在四种智能体方法和一个单次基线中取得了最高的惩罚后全任务得分和任务成功率。这些结果支持协调生物医学发现与 ML 工程，以将外部知识整合到可执行程序中，从而应对异构生物医学任务。

## Abstract
Agentic biomedical machine learning (ML) draws on complementary advances in biomedical evidence acquisition and executable program search. Existing systems connect aspects of these capabilities, but coordinating them throughout program search remains challenging. New evidence must guide candidate construction, execution outcomes must inform subsequent discovery and reuse, and validation demands must fit the search budget. We introduce BioDyad, which couples biomedical discovery and ML engineering through two hierarchies within Monte Carlo graph search. Its scientific hierarchy combines prior biomedical guidance with iterative discovery, then links biomedical plans to execution outcomes in memory for reuse across candidates. Its engineering hierarchy moves candidate programs from smoke execution, through train/validation evaluation, to full-data retraining. We evaluate BioDyad on the 76-task BioXArena benchmark under a two-hour per-task budget with three matched LLM backends. It achieves the highest penalized all-task score and task success rate among four agent methods and a one-shot baseline under each backend. These results support coordinating biomedical discovery and ML engineering to integrate external knowledge into executable programs across heterogeneous biomedical tasks.

## 2. 方法论

### 2.1 核心思想

- 在共享的**蒙特卡洛图搜索（MCGS）**骨干（继承自 MLEvolve）上叠加两个层级：
  - **科学层级（scientific hierarchy）**：先验指导 + 候选级迭代发现 + "方案—结果"生物医学记忆；
  - **工程层级（engineering hierarchy）**：冒烟执行 → 训练/验证评估 → 全数据重训与提交。
- 关键闭环：**生物医学证据改变程序，执行结果改变后续扩展可用的证据**。

### 2.2 问题形式化

- 任务 τ = (D, q, M, S, B)：公开数据、自然语言描述、评价指标、提交 schema、墙钟预算。
- 目标：在预算内求 p⋆ = argmax d_τ·m_τ(p)，约束 V_τ(p)=1（程序可执行且满足任务契约），其中 m_τ 为验证分数、d_τ 为优化方向。
- 图中节点状态：x_v = (p_v, π_v, e_v, m_v)，即程序、生物医学节点方案、执行结果、验证分数（后两者在执行前为 pending）。

### 2.3 科学层级

- **先验指导 g_τ**：搜索前运行一次**仅规划（plan-only）的 ReAct 智能体**，交替"推理—只读探测"，最多 6 个只读探测块，不训练候选模型；终止后编译为 g_τ = (F_τ, I_τ)，即已验证的数据发现 F_τ 与由这些发现支撑的生物医学推论 I_τ（BIO_PLAN）。它条件化后续节点发现，但**不规定模型族、不作为 MCGS 算子**。
- **节点级发现**：每次生成 draft / improvement / debugging 节点前，调用生物医学发现智能体，输入任务、先验指导、被选父节点与检索到的记忆，输出绑定"生物医学理由 + 可实现建模与验证策略"的 NODE PLAN π_{v′}。由于发生在早期候选已被评估之后，发现可**修正被支持的方向、放弃被反驳的方向或分支到新假设**。
- **生物医学记忆**：为每个节点存紧凑记录 k_v = (π_v, s_v, e_v, m_v, Δm_v, ℓ_v)（方案、搜索阶段、执行结果、分数、相对父节点的分数变化、成功/失败标记），生成代码前插入、执行后更新同一键记录。检索用**关键词与嵌入排序的倒数排名融合（RRF）**，每次取最多 2 个相关成功/待定方案、2 个相关失败、1 个不相似的成功方案，并去重。**失败与成功同样保留**，以区分"整合错误"与"可执行但无预测收益的改动"。
- 核心公式（文字化）：R_t = Retrieve(K_t, x_{v_t})；π_{v′} = Discover(τ, g_τ, x_{v_t}, R_t)；p_{v′} = Generate(p_{v_t}; g_τ, π_{v′}, R_t)；(e_{v′}, m_{v′}) = Engineer(p_{v′})。

### 2.4 工程层级

1. **冒烟执行（Smoke）**：静态检查 + 降成本冒烟运行，保留完整程序的**特征表示、模型与输出格式**；通过条件为无异常、报告所需验证分数、产出提交产物；否则记录失败并**直接返回 MCGS，不进入嵌套修复循环**。
2. **训练/验证评估**：抽取任务指标、校验产物与 schema，返回有效性与分数 m_v，更新 MCGS 与记忆中的方案—结果记录。
3. **全数据重训与提交**：搜索结束后按重训前验证分数选最优有效程序，其全量数据变体先经冒烟门控、只执行一次；若失败则保留原有效程序与提交。

### 2.5 两层级耦合与搜索调度

- MCGS 依据执行历史与剩余墙钟预算选节点：选根节点 → 生成新 draft；选无效候选 → 调试；选有效候选 → 改进。
- 继承 MLEvolve 的选择策略：**UCT**（Q_v/N_v + C_t·√(log(N_pa(v)+1)/N_v)）平衡奖励与探索；**精英引导采样**按分数排名倒数概率采样 top-K 有效候选。
- **预算依赖配置**：以已用预算比例 ρ_t 决定 UCT 概率 w_exp(ρ_t)，ρ_s=0.5、ρ_e=0.7、w_min=0.2——早期探索、后期利用；精英池在 ρ_e 前最多 5 个、之后 3 个，每分支分别最多 3/2 个。

## 3. 实验设计

- **Benchmark**：BioXArena，76 个留出预测任务，覆盖 9 个领域（序列、单细胞、结构、网络生物学、化学生物学、扰动动力学、表型—疾病、影像、文本整合），其中 46/76 任务跨多种模态家族。每个任务胶囊含描述、公开训练/测试输入、原生格式资产、样例提交与任务专属指标；测试标签与评测器隐藏。
- **执行协议**：无网络沙箱，**每任务 2 小时墙钟上限**（含先验规划、候选发现与评估、最终重训与提交全流程），固定 CPU/GPU 配额，写出 submission.csv；允许通过本地挂载的数据缓存引入额外生物医学知识，BioDyad 在发现阶段使用本地 **Biomni** 数据与工具。
