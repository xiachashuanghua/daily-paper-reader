## 摘要
生命科学知识图谱通过SPARQL提供大量结构化数据，但每种资源使用自己的模式、标识符和链接。TogoMCP通过提供精选的元数据互操作交换文件来帮助语言模型智能体查询这些资源。创建和维护这些文件仍然需要语言模型辅助起草、验证和人工审查。我们研究了\emph{实时模式接地}，其中智能体直接从当前端点获取回答问题所需的模式证据。我们提出了\textsc{autoschema}，一个无需训练的通用实时模式接地框架。它检查实时模式，将问题中的实体名称映射到图标识符，探索关系路径，并在迭代查询构建期间寻找资源之间的可能连接。我们以TogoMCP作为主要比较框架。我们在资源聚焦的生物医学KGQA、多资源生物医学KGQA、基于BioASQ任务B的纵向生物医学语义问答以及化学知识图谱迁移到先前未记录的RDF图上评估了\textsc{autoschema}。\textsc{autoschema}在生物医学KGQA任务中相比TogoMCP提高了平均事实性准确率，并在纵向BioASQ评估中给出了一致的增益。它还在核心评估中减少了迭代预算耗尽，并平均使用更少的工具调用。迁移研究提供了初步证据，表明实时模式接地可以支持不规则和先前未见过的图，而无需首先创建精选模式文件。

## Abstract
Life science knowledge graphs make large collections of structured data available through SPARQL, but each resource uses its own schema, identifiers, and links. TogoMCP helps language model agents query these resources by providing curated Metadata Interoperability Exchange files. Creating and maintaining these files still requires language model assisted drafting, validation, and manual review. We study \emph{live schema grounding}, where an agent obtains the schema evidence needed for a question directly from the current endpoints. We present \textsc{autoschema}, a general framework for live schema grounding that requires no training. It inspects live schemas, maps entity names in a question to graph identifiers, explores relation paths, and finds possible connections between resources during iterative query construction. We use TogoMCP as our main comparison framework. We evaluate \textsc{autoschema} on Resource Focused Biomedical KGQA, Multi Resource Biomedical KGQA, Longitudinal Biomedical Semantic QA over BioASQ Task B, and Chemistry Knowledge Graph Transfer to a previously undocumented RDF graph. \textsc{autoschema} improves mean factoid accuracy over TogoMCP in the biomedical KGQA tasks and gives consistent gains in the longitudinal BioASQ evaluation. It also reduces iteration budget exhaustion and uses fewer tool calls on average in the core evaluation. The transfer study gives preliminary evidence that live schema grounding can support irregular and previously unseen graphs without first creating a curated schema file.

## 1. 核心问题与研究背景

生命科学领域的知识图谱以RDF/SPARQL为标准进行发布，但由于各资源独立维护、使用不同的标识符、谓词和schema，研究者查询这些异构图谱面临很高的技术门槛。现有方法（如TogoMCP）通过提供人工维护的MIE（Metadata Interoperability Exchange）文件向LLM代理注入schema上下文，能显著提升文本到SPARQL的生成质量，但存在三大问题：

- **MIE文件创建成本高**：需要LLM辅助起草、端点验证和人工审查，过程耗时且消耗大量token。
- **更新滞后**：端点schema发生变化时，静态文件可能过期。
- **隐私受限**：私有RDF数据可能不允许通过托管模型API进行外部处理。

本文提出 **AutoSchema**，一种无需训练的通用实时schema grounding框架，让agent在提问时直接从实时端点获取所需的schema证据，从而避免依赖预先生成的模式文件。

## 2. 方法论详解

### 2.1 核心思想

AutoSchema的核心是**实时schema grounding（live schema grounding）**：模型智能体在查询过程中按需从实时端点的SPARQL接口获取schema证据，而不是提前加载完整的schema文件。整个框架通过以下原则运作：

- **按需获取**：仅在agent需要时才请求schema证据，避免加载完整schema。
- **分模块覆盖**：四个模块分别对应查询构建中的四个关键决策：选源、实体解析、关系发现、跨库连接。
- **与agent解耦**：模块只查SPARQL端点、不调用LLM，输出紧凑的grounding证据，与具体agent和模型无关。

形式上，给定异构RDF图集合 \(D = \{G_1, \ldots, G_m\}\) 和自然语言问题 \(q\)，agent需完成四项grounding决策：
1. 确定相关的数据源
2. 将问题中的实体名称解析为图标识符
3. 找到表达请求的关系和路径
4. 连接多个资源（当单个图谱不够时）

### 2.2 四个核心模块

| 模块 | 函数 | 功能 |
|------|------|------|
| 源总结（Source Summarization） | `get_rdf_schema(database, entity_class="")` | 返回命名图范围、频繁类计数、示例实体IRI、谓词IRI、观察到的值类型和示例SPARQL查询 |
| 实体解析（Entity Resolution） | `search_rdf_entity(database, keyword, limit=10)` | 搜索label/title/name/accession等谓词，识别OBO、UniProt等生物医学accession形式，返回候选实体IRI |
| 关系与路径发现（Relation & Path Discovery） | `expand_entity(database, entity_iri)` | 在一次SPARQL请求内获取直接属性和经过最多三层嵌套空白节点的路径，返回谓词组、叶子值和可执行的SPARQL pattern |
| 跨库桥接（Cross-Database Bridging） | `get_cross_db_bridges(database_a, database_b)` | 基于标识符转换服务、直接IRI复用或共享属性名返回桥接候选和join骨架 |

### 2.3 实现细节

- **实时索引**：首次访问某源时构建有界实时索引（≤25个类、每类≤40个谓词、每类采样≤300个实例），缓存于内存和磁盘，可刷新重建。
- **MCP服务器**：AutoSchema实现为独立的MCP（Model Context Protocol）服务器，核心函数均为异步。
- **Agent循环**：agent先规划，再调用所需模块获取证据，编写候选SPARQL，执行后根据结果反思并迭代；两次失败则强制更换谓词/源/工具而非重复尝试。

### 2.4 示例流程

以“A strain is associated with CCM 2634 and entity 11225. What value is shared?”为例：
1. `search_rdf_entity`解析“CCM 2634”→ 集合记录20378。
2. `expand_entity`发现`describesStrain`属性 → 链接到strain/7366。
3. 解析“11225”→ strain/11225。
4. 比较两个strain的属性，发现都有`hasPhylum` → 共享值Actinobacteria。

### 3.2 对比方法

- **No schema**：只有数据库名和查询执行，无schema证据（下界）。
- **TogoMCP**：提供LLM辅助起草并人工审查的MIE文件。
- **AutoSchema**：实时grounding模块，无MIE。
- **Single shot**：AutoSchema的消融版本，每问题每模块最多调用一次。

### 3.3 模型与评估

- 模型：`gpt-oss-120b` 和 `gemma4-31b`（均为开放权重，用vLLM本地服务）。
- 迭代预算：20次，报告达到上限的频率（limit rate）。
- 指标：factoid准确率（top-1）、list F1、yes/no准确率，通过精确匹配、词法匹配和LLM裁判三级匹配确定。
- 每个结果报告3次运行的均值±标准差。

## 4. 资源与算力

- 文中明确说明：两个模型均通过vLLM在单个NVIDIA A100 GPU上本地服务。

## 6. 主要结论与发现

1. **AutoSchema在生物医学KGQA上优于TogoMCP**：资源聚焦任务中gpt-oss-120b的factoid准确率从0.198提升到0.260，gemma4-31b从0.258提升到0.281；多资源任务改善更大，gpt-oss-120b以0.203超过TogoMCP的0.167。
2. **纵向BioASQ上一致提升**：在6个年度测试集中，AutoSchema均有更高的factoid准确率（提升范围+0.023到+0.078），展示了时间鲁棒性。
3. **降低迭代预算耗尽率并减少工具调用**：在核心评估中平均使用更少的工具调用（如gpt-oss-120b从12.91降到11.13），延迟相近。
4. **迁移到不规则未见图谱有效**：tmQM-RDF上factoid准确率从0.273提升到0.394，limit rate从35.9%降至23.1%。
5. **单次grounding已足够大部分场景**：消融显示资源聚焦任务中迭代vs单次差别不大，但多资源任务中迭代访问对gpt-oss-120b更有利。

## 7. 方法亮点与优势

- **免训练、免预建文件**：无需训练模型或预先创建schema文件，新图接入成本极低（37秒索引vs 28分钟MIE创建）。
- **通用可靠**：仅依赖SPARQL端点标准查询接口，可适用于不同领域、不同schema复杂度的图。
- **模块化设计**：四项能力可独立使用，agent按需调用，实现从“大而全的schema dump”到“精而准的按需证据”的范式转变。
- **本地化部署友好**：仅使用开放权重模型，无外部API依赖，适合处理私有数据场景。
- **可解释性**：每个答案可回溯到具体的实体解析、路径发现证据，支持溯源验证。
- **实证严谨**：多任务、多模型、多次运行并报告标准差，对比框架控制严格。

## 8. 不足与局限

### 8.1 实验设计的局限

- **多资源KGQA结果噪声大**：运行间标准差较大，增益方向稳定但幅度不确定。
- **迁移实验证据不足**：仅1次运行、39个问题，且无多模型重复，外部效度有限。
- **桥接模块使用率低**：多数多资源问题实际通过实体展开发现共享值解决，桥接工具未被充分利用，其有效性缺乏直接验证。
- **未报告统计显著性检验**：无法判断观测到的准确率差异是否在统计上显著。

### 8.2 方法层面的局限

- **有界索引可能遗漏关系**：采样上限（25类、40属性/类、300实例/类）意味着未观察到的关系可能存在，工具无法证明关系的不存在。
- **生成的查询依赖于agent能力**：框架提供证据但不保证查询正确性，最终质量受LLM推理能力的制约。
- **外部端点负载**：实时查询会增加公共SPARQL端点的负载，密集使用可能引发速率限制或服务问题。

### 8.3 伦理与隐私风险

- 查询发送到端点可能泄露研究问题中的科学术语。
- 生物医学场景下错误答案可能带来风险，作者明确声明该工具仅供研究和信息检索，不适用于临床决策。
- 未收集个人数据、不涉及人类参与者，但部署敏感场景需要访问控制、缓存和速率限制。

### 8.4 总体评价

AutoSchema提出了一个有价值的、务实的范式转变——从静态schema文件转向动态的、问题驱动的实时模式发现。该方法设计清晰、实验覆盖较广，但结论的强健性仍需更多测试集、更多模型和统计检验来支撑。
