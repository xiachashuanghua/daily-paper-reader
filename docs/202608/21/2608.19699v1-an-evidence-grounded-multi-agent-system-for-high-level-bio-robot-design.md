## 摘要
本文中，生物机器人是一种工程化的活体或生物混合系统，其中活细胞执行一个或多个核心功能，如感知、信息处理、驱动或输出。我们专注于基于细胞的功能由基因电路编程的系统；物理运动是可选的。设计此类系统需要将应用需求转化为感知、逻辑或记忆、输出、组装、宿主和遏制模块，同时将每个选择建立在可追溯的部件和证据基础上。我们提出了micro_biorobot_agent，一个基于Qwen3.5-27B的离线多智能体系统。该系统结合了需求分析、模块特定检索、候选组装、冲突检查、局部修复、独立审查和验证，集成库包含23,762条记录，涵盖生物部件、测量组合、文献支持的关联和驱动证据。确定性输出检查使最终报告与检索到的部件集对齐，并纠正错误空白、不支持的部件提及和来源跟踪错误。在作者开发的两个各含50个查询的评估集上，系统获得的平均总分为7.35和8.04，在七个评估系统中最高；在场景设计方面，它超出亚军2.23分。一项50次查询的配对消融显示，来源跟踪检查将错误空白事件从15次减少到3次，减少80%，并将来源准确性提高0.75分。本文报告了基于Qwen3.5的v1系统，并评估了高层设计报告，而非实验验证的电路。

## Abstract
In this paper, a bio-robot is an engineered living or biohybrid system in which living cells perform one or more core functions, such as sensing, information processing, actuation or output. We focus on systems whose cell-based functions are programmed by genetic circuits; physical movement is optional. Designing such a system requires translating application requirements into sensing, logic or memory, output, assembly, host and containment modules, while grounding each choice in traceable parts and evidence. We present micro_biorobot_agent, an offline multi-agent system built on Qwen3.5-27B. The system combines requirement analysis, module-specific retrieval, candidate assembly, conflict checking, local repair, independent review and validation over an integrated library of 23,762 records covering biological parts, measured combinations, literature-supported relationships and actuation evidence. Deterministic output checks align the final report with the retrieved part set and correct false gaps, unsupported part mentions and source-tracking errors. On two author-developed evaluation sets of 50 queries each, the system obtains mean overall scores of 7.35 and 8.04, the highest among the seven evaluated systems; on Scenario Design it exceeds the runner-up by 2.23 points. A 50-query paired ablation shows that the source-tracking check reduces false-gap incidents from 15 to 3, an 80% reduction, and increases source accuracy by 0.75 points. This paper reports the Qwen3.5-based v1 system and evaluates high-level design reports rather than experimentally validated circuits.

- **核心问题**：设计是主要瓶颈。一条简短的需求（如"在低氧肿瘤组织中激活并记录到达的细菌微型机器人"）就涉及感知模块、逻辑/记忆模块、输出报告器、组装支架、宿主/载体选择和遏制模块。设计师需要在iGEM、FPbase、SBOL等数据库中搜索真实部件，并检查序列、接口、宿主范围、证据和缺失边界。

- **研究意义**：生物机器人电路设计是系统设计问题而非简单的部件查询，需要平台能够推断未明说的目标和前置模块，选择有明确证据和接口信息的候选方案，准确陈述空白，并生成工程师可审查的设计报告。

## 2. 方法论

### 核心思想：共享工作空间（黑板系统）多智能体架构

- 不将检索结果直接传给单个大语言模型，而是通过**共享结构化设计记录**协调约二十多个专门组件（LLM 智能体、确定性规则、验证器）协作完成设计。
- 各阶段写入带来源标签的报告，使最终报告可追溯到具体组件和证据，可被组装、质询和修复，而非一次性生成。

### 主要工作流程

| 阶段 | 组件 | 目的 |
|------|------|------|
| 需求分析 | 分析智能体+监督者 | 识别目标、约束和所需模块 |
| 证据搜索 | 场景与证据智能体 | 收集设计模式、证据和安全需求 |
| 部件检索 | 模块特定检索智能体 | 为每个所需模块查找候选部件 |
| 设计 | 设计智能体 | 组装多个内部一致的候选方案 |
| 审查与修复 | 冲突检查器、修复规划器和三个审查智能体 | 检查接口、生物机制和证据；修订受影响模块 |
| 验证 | 七个规则验证器 | 检查证据、完整性、兼容性、可行性、安全性、无支撑声明和输出格式 |

### 集成证据库

- **总计23,762条记录**：6,009条生物部件记录、17,715条测量的启动子-RBS组合或文献支撑关系记录、38条物理驱动方法/证据记录。
- 数据来源：iGEM Registry（4,000条带DNA序列的部件）、Kosuri 2013（12,480条测量启动子-RBS对）、FPbase（1,040条荧光蛋白记录，其中301条通过NCBI E-utilities补充了验证的核苷酸编码序列）、文献关系（5,235条，865个独特DOI）。
- **分离规则**：默认搜索使用精选索引；大型辅助数据集仅在需要时搜索。添加1,383条论文记录使top-5目标命中率从0.714降至0.619，移除后恢复。
- 证据分四级：测量部件组合、验证DNA序列、文献支撑关系、基于功能的建议。
- 库分层管理：源层、标准化层、搜索层，版本化更新。

### 部件角色分配算法

- 将每个检索记录分配到九种生物角色之一（金属传感器、代谢传感器、通用传感器、重组酶、逻辑门、群体感应、荧光输出、杀伤开关、物理驱动），不改变搜索排名。
- 若模块无候选，仅对通用角色（逻辑、记忆、通用感知、报告、遏制）启用回退，不用于情境特定角色（如金属感知），防止了9次不正确的代谢部件分配。

### 规则基础输出检查

- **假空白修正**：检索列表有合适部件但报告说模块为空时，替换为排名最高的合适部件。
- **不支持的部件标签**：报告展示了未检索到的库部件时，标记为"外部建议"。
- **来源标签修正**：报告错误地把已检索部件标记为外部时，改为"已检索，可用"——精确ID匹配，长ID优先检查。

## 6. 主要结论与发现

- **系统排名**：micro_biorobot_agent在两个50查询子集上均排名第一——Basic Design得分7.35（高出亚军0.96），Scenario Design得分8.04（高出亚军2.23）。

- **来源标签修正效果**：错误空白从15降至3（−80%），来源准确性提升+0.75，总体分提升+0.32，兼容性提升+0.31。

- **与基线差距**：证据检索本身不足以保证报告质量——GPT-5.5+LS+RAG在场景设计的设计细节（3.97 vs 7.51）和兼容性（4.41 vs 7.78）上明显落后。
- **关键认识**：有检索到部件却说模块为空会同时降低覆盖率和来源准确性；确定性约束优于依赖模型自洽性。

- **共享工作空间架构**：所有智能体输出存储在带显式来源链接的结构化设计记录中，过程可检查、可测试，而非一次性生成。
