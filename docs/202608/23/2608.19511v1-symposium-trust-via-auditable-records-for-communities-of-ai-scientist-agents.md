## 摘要
Symposium 是一个正式的框架和实际实现，用于记录小型科学研究社区所部署的人工智能代理的操作行为。Symposium 提供长期、不可篡改的智能体驱动研究活动历史，留下可审计的分析、假设、数据和科学讨论痕迹。这种已发布制品的共享记录使代理能够在前人工作基础上继续推进，并保留了研究人员和代理进行基于目的性的信任评估所需的证据。Symposium 捕获科学论点，包括结构化声明、细粒度证据引用、假设以及明确声明哪些材料可以作为或不可以作为证据。Symposium 不同于 AI 联合科学家代理或集成式 AI 研究环境；它是一个将科学社区的持久历史与其运行所依赖的代理及其他系统分离开来的框架。它假设一个社区将在快速演变的环境中采用多样化的 AI 系统。提供了发布基础设施、代理提示组件及其文档的工作实现，使用户能够快速设置并运行自己的 Symposium 社区。

## Abstract
Symposium is a formal framework and practical implementation to record the operation of AI agents deployed by small scientific research communities. Symposium provides long-term, immutable histories of agent-driven research activity, leaving auditable trails of analyses, hypotheses, data, and scientific discourse. This shared record of published artifacts enables agents to build on prior work and preserves the evidence researchers and agents need to make purpose-dependent trust assessments. Symposium captures scientific argument, including structured claims, fine-grained evidence citations, assumptions, and explicit declarations of what material may and may not be used as evidence. Symposium differs from AI co-scientist agents or integrated AI research environments; it is a framework that separates a scientific community's durable history from the agents and other systems that operate on that history. It assumes that a community will use diverse AI systems in a rapidly evolving environment. A working implementation of the publication infrastructure, agent prompt components, and documentation are provided to enable users to rapidly set up and run their own Symposium community.

## 1. 核心问题与整体含义

### 研究动机与背景

- **信任危机**：AI 智能体已能执行文献分析、实验设计、数据分析、假设生成等科研任务，速度远超人类，但**并不完美**——它们可能捏造事实和引用、误读真实来源，或产出逻辑混乱但说服力强的假设。
- **对齐风险**：随着模型能力增强，智能体可能追求操作者未设定的目标，甚至出现欺骗、共谋行为（论文引用了近期 AI 安全事件）。
- **协作需求**：实验室/项目/公司规模的研究社区将使用多种不同的 AI 助手，且随技术发展不断更换；不同世代的智能体需要互相复用和批判性审查彼此的工作。
- **规模问题**：AI 可在一天内生成并测试数十甚至上百个假设，远超人工记录与审查的能力范围。
- **核心洞察**：需要建立类似科学出版制度的机制——目标不是"认证每个结论为真"，而是**创造信任可被评估的条件**：读者可以接受、拒绝、重复分析、追溯引用或选择依赖某项结论。

### 论文提出的总体方案

Symposium 是一个形式化框架与实际实现，将小型科学社区的**持久历史**与运行其上的**各类 AI 系统解耦**，通过一个不可篡改的共享记录（CommunityRecord）保存智能体发布的所有研究产物，使多样化的智能体和人类研究者都能基于此评估信任、复用成果。

## 2. 方法论

### 核心设计思想

- **社区记录（CommunityRecord）是历史，而非知识图谱**：它只保存按时间排序的、由成员发布的 Artifact 序列，不包含对某一事实/实体/概念的权威表示，也不建模共识信念。
- **信任是基于目的的判断**：作者在 Argument 中明确阐述其动机（purpose）和错误后果；后续读者将作者语境与自身目的（如下一步实验还是临床决策）比较，自主判断可信程度。
- **成员判断，而非系统裁决**：系统不负责评判 Artifact 的质量或科学正确性；社区成员（通常是智能体）自行评判与审查。
- **以形式合规引导意图合规**：大多数属性是自由文本，但为"必填"属性——这相当于一个被校验软件强制执行的"提示"，迫使发布智能体考虑该属性的意图。

### 关键元素：Members、Artifacts 与 CommunityRecord

- **Members**：社区成员，通常为 AI 智能体，也可以是工具、人类研究者或自动化流程。
- **Artifacts**：成员发布到 CommunityRecord 的基本数据单元，不可变、具名、有时间戳和归属。Artifact 是属性图结构，可包含 Objects 和关系，均可附加任意属性。

### 核心 Artifact 类型

| 类型 | 用途 |
|---|---|
| **Argument** | 记录科学论证：声明、证据、假设、推理与结论 |
| **Data** | 发表科学数据（实验观测或分析导出值） |
| **Analysis** | 记录一次已执行的分析程序的具体事件，含输入、工具、执行过程 |
| **Model** | 表示目标系统的简化可复用表征，记录建模选择 |
| **ScientificPublication** | 导入的外部科学文献（论文、报告等） |
| **NonGroundable** | 明确标记为不可作为证据的内容（计划、总结等） |
| **Message** | 成员间的定向通信，不可作为证据 |

### Argument 的结构（最核心的 Artifact）

- **Assertion**：声明对象，必填自由文本 `claim` 和 `scope` 属性；每个 Argument 有且仅有一个**主声明**（primary Assertion）。
- **depends_on**：将复杂声明分解为前驱声明的依赖层级。
- **Ground**：将断言与证据连接的节点，使用 `grounded_by` 中性表述（不预设支持或反对）；可含 `criterion` 属性指定与声明不一致的数据/分析标准（即可证伪性判断），也可无 criterion。
- **Assumption**：无证据支撑但被明确纳入论证的声明，必须提供 `rationale`（理由）。
- **必填自由文本属性**：`verdict`（结论，可细致化而非简单的二值判定）、`rationale`（推理）、`purpose`（动机与决策语境）。

### 关键机制：证据声明与内容寻址引用

- **Groundable 声明**：任何内容要被引为证据，必须由发布者通过 Content Object 显式声明 `groundable=true`——证据是发布者明确"背书"的，而非读者自行认定的。
- **细粒度内容寻址**：引用可指向 Artifact、Object、属性，甚至数据表的一个单元格、文本中的一句话、光谱中的一个峰，通过 schema reference 实现。
- **例外机制**：Argument 的主声明可以被后续 Argument 直接引用为证据（类同于论文引用：接受前文结论而不重新论证），留下清晰的可追溯链。
- **实体导入**：导入外部来源（论文、数据库、软件）时需记录 `import_method`，导入是成员对源数据的"呈现"而非权威副本。
- **版本与更正**：Artifact 不可修改；更正通过发布新 Artifact 并用 `supersedes` 指向旧 Artifact，且必须提供 `supersedes_rationale`。

## 6. 主要结论与发现

1. **可审计记录是实现多智能体科研信任的基础**：借鉴科学出版制度的"条件创造"逻辑——重点不是认证真实性，而是让信任可被评估。
2. **持久历史与运行系统解耦是必要设计**：社区历史不应绑定于某一特定智能体或研究环境，否则技术迭代会导致知识断层。
3. **证据声明机制（groundable）有效区分了证据与非证据**：将"作者为自己内容背书"的出版实践形式化，提升了证据链的精确性。
4. **细粒度内容寻址引用**使 argument 可精确指向数据点、文本片段等，超越传统论文级引用的粒度。
5. **Arg 分级结构（主声明、依赖关系、Assumption、Ground + criterion）**可支持复杂假设的结构化评估。
6. **"非可发表工作"（方法的优化实验、阴性结果、死胡同）的永久保存**具有独特价值——保留"实验室的隐形知识"，这比追求"辉煌假设"更有实践意义。
7. **框架的扩展性设计（极简词汇 + 自由文本 + 类型扩展）**使其能适应快速演化的 AI 生态。
8. 提供了可运行的完整实现（GitHub: ndexbio/symposium），降低采用门槛。

## 7. 优点

- **哲学清晰**：明确区分"知识图谱"与"历史记录"，回避了对科学共识建模的困难。
- **将信任看作目的相关判断而非二元评分**，更贴近科研实践的真实决策逻辑。
- **强制声明机制（必填属性、groundable 声明、supersedes_rationale）**以最小约束让智能体被迫思考意图，同时避免过度结构化限制灵活性。
- **细粒度内容寻址**设计精巧，支持从 Artifact 级到单元格级的引用，且通过 Content Object 的 schema 机制实现了任意粒度的可扩展性。
- **对证据非独立性的显式关切**（如披露两个 Ground 指向同一研究的两个部分）体现了对科学推理深层问题的敏锐把握。
- **"成员判断，系统不裁决"**的设计原则务实，避免了将科学评价的复杂决策不恰当地委托给系统。
- **重视非可发表工作和实验室隐性知识的保存**，提供了不同以往的 AI 科研价值视角。
- 实现完整（基础设施 + 提示工程组件 + 文档），并非仅停留在纸面设计。

## 8. 不足与局限

- **缺乏实证验证**：没有真实科研社区长期使用的经验数据；合成示例无法证明框架在大规模（数百智能体、数十年记录）场景下的可行性与实用性。
- **自由文本带来的语义障碍**：如何自动识别不同 Argument 中"同一声明"（相同的 claim 和 scope）缺乏通用解决方案，论文承认这一点且未提供缓解策略。
- **对成员的信任风险**：系统强制的是"形式合规"而非"意图合规"；恶意或不称职的智能体仍可能发布看似合规但实质误导的 Artifact。虽然社区可以有审查机制（论文建议发布"综述期刊"），但没有系统化保障。
- **可扩展性瓶颈未验证**：在快速发展、成员频繁更换的社区中，新世代智能体如何有效理解和利用旧版本规格下的 Artifact，仅靠版本声明机制可能不够。
- **操作层面的导航与检索问题**：CommunityRecord 本身不支持正向引用追踪等功能，依赖外部搜索索引或补充 Model——这在长期大规模运行下可能成为瓶颈。
- **未探讨经济与治理问题**：谁部署/维护记录基础设施？谁有权成为成员？恶意成员的治理机制如何设计？论文未深入讨论。
- **资源消耗未知**：特别是在高吞吐、大量智能体高频发布的场景下，系统的存储与计算成本未被评估。
- **无对比实验**：与相关框架（如 ScienceForge、Traxia、APP 等）在真实可用性、采纳成本、表达力等方面的系统性对比缺失。
