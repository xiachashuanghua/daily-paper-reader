## 摘要
生物系统本质上是多层的：相同的实体——基因、细胞或细菌物种——同时参与性质上不同类型的相互作用，每种相互作用都携带互补的信息，而任何单一的关系视角都无法捕捉这些信息。使用单层工具分析此类系统，或将各层合并为单层投影，会系统性地丢弃层间依赖关系，并可能产生关于中心性、社区结构和鲁棒性的误导性结论。多层网络形式主义解决了这一问题，而\texttt{muxViz}建立了首批用于其结构分析的综合工具包之一，但其仅限R语言的界面和密集的数据结构限制了其在大规模生物网络中的应用。我们介绍了\textit{muxvizpy}，这是一个Python库，基于SciPy和PyTorch构建的稀疏线性代数栈，重新实现并扩展了\texttt{muxViz}的分析目录。Muxvizpy通过统一且可组合的API提供七个类别，并在合成Erdős–Rényi和Barabási–Albert多层网络上与\texttt{muxViz}进行了数值验证，同时在大规模下显著降低了峰值内存和墙钟时间。我们通过一个病毒-人类蛋白质相互作用多层网络展示了其适用性，在该网络中进行某些结构分析此前是不可行的。\\[2pt] muxvizpy根据MIT许可证免费提供，网址为https://github.com/CoMuNeLab/MuxVizPy。所有已实现指标的数学定义见附加文件。

## Abstract
Biological systems are inherently multilayered: the same entities---genes, cells, or bacterial species---participate simultaneously in qualitatively distinct types of interactions, each carrying complementary information that no single relational view can capture. Analysing such systems with single-layer tools, or by collapsing layers into a monoplex projection, systematically discards inter-layer dependencies and can yield misleading conclusions about centrality, community structure, and robustness. The multilayer network formalism addresses, and \texttt{muxViz} established one of the first comprehensive toolkits for its structural analysis, but its R-only interface and dense data structures limit applicability to large biological networks. We introduce \textit{muxvizpy}, a Python library that reimplements and extends the \texttt{muxViz} analytical catalogue with a sparse linear-algebra stack built on SciPy and PyTorch. Muxvizpy exposes seven categories through a unified, composable API and is numerically validated against \texttt{muxViz} on synthetic Erdős--Rényi and Barabási--Albert multiplex networks while substantially reducing peak memory and wall-clock time at scale. We illustrate its applicability on a virus--human protein-interaction multiplex in which computing some structural analysis was unfeasible. \\[2pt] muxvizpy is freely available under the MIT licence at https://github.com/CoMuNeLab/MuxVizPy. Mathematical definitions of all implemented metrics are provided in the Additional File.

## 2. 方法论

### 2.1 核心设计原则

- **Sparse-first（稀疏优先）**：所有超邻接矩阵和张量均存储为 SciPy CSR 稀疏矩阵或 PyTorch COO 稀疏张量；层间耦合块在未显式提供时自动生成。
- **Composable（可组合）**：库暴露少量基础数据结构构造器，高层指标均从这些基础构件推导；用户可提供自定义超邻接矩阵或利用 mode-1 展开转换张量后调用任意指标。
- **Validated（经过验证）**：每个指标都有与 muxViz 在共享合成网络上输出的数值对照测试。

### 2.2 数据结构

- **基本对象**：邻接张量 **M** ∈ ℝ^(N×N×L×L)，以 PyTorch COO 稀疏张量存储，保留节点数 N 和层数 L 的维度信息（这些信息在展平为 NL×NL 矩阵时会丢失）。
- **Mode-1 展开**：对大多数结构指标，张量通过 mode-1 展开转换为超邻接矩阵 **A** ∈ ℝ^(NL×NL)，存储为 SciPy CSR 稀疏矩阵。对角块（N×N）编码层内邻接，非对角块编码层间耦合。
- **类别耦合**：对于节点对齐的类别耦合多重网络（最常见的实际情形），耦合块退化为标量加权的单位矩阵，muxvizpy 以隐式方式存储。
- **输入格式**：五列边表 CSV（node.from, layer.from, node.to, layer.to, weight），与 muxViz 边表格式兼容。

### 2.3 七类分析指标

| 类别 | 代表性指标 |
|------|-----------|
| **Versatility（多面性）** | 特征向量中心性、Katz 中心性、PageRank、随机游走、Hub/Authority、多度/多强度、多层 k-core |
| **Mesoscale（中尺度）** | 多层模块度（multislice modularity）、层间度同配性、局部聚类系数 |
| **Topology（拓扑）** | 最大连通分量（LCC）、最大可行分量（LVC/LIC）、路径统计与最短路径相似性 |
| **Information Theory（信息论）** | 冯·诺依曼熵、Jensen–Shannon 散度 |
| **Decomposition（分解）** | 典型多面分解（CP/PARAFAC） |
| **Global Descriptors（全局描述符）** | 平均全局聚类系数、全局边重叠与重叠矩阵 |
| **Percolation（渗流）** | 顶点渗流（vertex percolation） |

### 2.4 精确与近似算法双路径

- 许多中心性指标本质上归结为两类线性代数问题：**求解大型稀疏线性系统** `(I − αAᵀ)x = 1`，或**求解占优特征向量**。
- **Katz 中心性**：
  - 精确路径：稀疏 LU 分解（`spsolve`）。
  - 近似路径 1：Neumann 级数矩阵自由定点迭代（收敛速率受 α·ρ(A) 控制，接近谱极限时变慢）。
  - 近似路径 2：ILU 预条件 GMRES / BiCGSTAB Krylov 迭代（在病态区域显著加速，内存可控）。
  - 参数选择：α = (1−ε)/λ_max(A)，尽量接近谱极限。
- **PageRank / 随机游走中心性**：
  - 精确路径：稀疏特征分解（ARPACK k=1），利用 Perron–Frobenius 定理保证占优特征向量唯一。
  - 近似路径：幂迭代法，收敛比率为 α（阻尼因子，默认 0.85），收敛快且稳健。
- **CP 分解**：重新实现交替最小二乘（ALS）算法，利用稀疏 MTTKRP（Matricized tensor times Khatri-Rao product），计算代价为 O(nnz(M)·R) 而非张量体积 N²L²。

### 2.5 模块化公式示例

- **Katz 中心性**：x = (I − αAᵀ)⁻¹ **1**，α ∈ (0, 1/λ_max(A))
- **PageRank**：G = αT + (1−α)**1v**ᵀ，求 Gᵀπ = π 的平稳分布
- **模块度**：Q = (1/2μ)Σ [A_ij^α − γ_α(k_i^α k_j^α / 2m_α)]δ(αβ) + δ_ij C_jαβ]·δ(g_iα, g_jβ)
- **CP 分解**：M ≈ Σ_{r=1}^{R} λ_r a_r ∘ b_r ∘ c_r ∘ d_r

## 6. 主要结论与发现

- **规模扩展**：muxvizpy 将可分析的多层网络规模**扩大超过一个数量级**——muxViz 在约 10⁷ 边附近触及时限或内存上限，而 muxvizpy 可在约 10⁸–10⁹ 边上完成 versatility 指标计算。
- **数值一致性**：与 muxViz 共享的指标达到 **Pearson r = 1.0000**，中位 MARE 介于 1.3×10⁻⁴ 至 8.0×10⁻⁴ 之间，验证了数值正确性。
- **性能优势**：稀疏迭代特征求解器在数秒内完成最大规模网络的 Eigenvector、PageRank、Hub 和 Authority 中心性计算；ILU 预条件 Krylov 求解器在 BA 网络上消除了直接 LU 因填充导致的容量崩溃问题。
- **CP 分解效率**：稀疏 ALS 的计算代价随 nnz(M) 线性增长，而 dense tensorly 的 parafac 受张量体积 N²L² 限制，在中等规模即触顶。
- **生物应用成功**：在病毒–人类 PPI 多层网络中，多层描述符足以区分致癌与非致癌病毒，并识别出与致癌性相关的候选宿主基因，证明大规模多层分析可用于生物学发现。
- **全局聚类是最大瓶颈**：基于三角形计数的全局聚类在两个工具中差距最悬殊，muxvizpy 内存低 1–2 个数量级。

## 7. 优点

- **稀疏优先架构**：从根本上解决密集数据表示的可扩展性瓶颈，内存峰值随边数而非张量体积增长。
- **精确/近似双路径统一框架**：同一指标既提供精确求解器又提供可扩展的近似求解器（Neumann、GMRES/BiCGSTAB+ILU、幂迭代），用户可根据网络规模、条件数和精度要求权衡选择。
- **与 Python 科学计算生态无缝集成**：原生支持 SciPy、PyTorch、graph-tool、Scanpy/AnnData 等主流工具，降低生物信息学工作流中采用多层分析的障碍。
- **统一的 API 和组合式设计**：7 类指标通过一致接口暴露，用户可自定义超邻接矩阵或张量后直接调用任意指标。
- **数值验证严谨**：每个共享指标均与 muxViz 对照，使用 Pearson r 和 MARE 量化一致性；CP 分解对照 tensorly 并解决因子匹配歧义。
- **开源可复现**：MIT 许可证，提供完整数学定义附文件。
- **性能基准透明度高**：同时测量墙钟时间和峰值内存，明确报告超时/超内存界限，便于客观比较。

## 8. 不足与局限

- **精确谱方法的固有瓶颈**：精确 LU 分解在 BA 网络（无标度拓扑）上因填充（fill-in）退化严重（约 10⁶ 边即内存溢出）；近似迭代路径缓解但未消除此约束。
- **验证覆盖不完整**：
  - 与 muxViz 的验证仅限于两个工具共有指标，排除了 muxvizpy 独有的扩展功能。
  - 信息论指标仅在 BA 网络上验证（muxViz 在 ER 上失败）。
  - 大规模网络（10⁷ 边以上）没有地面真值参照，只能依赖小规模推断。
- **独有的指标缺乏第三方基准**：k-core、渗流、LVC/LIC、CP 分解等仅通过单元测试（小规模解析解）或单一生物用例间接验证，客观性证据较弱。
- **分解模块有限**：目前仅实现 CP/PARAFAC 分解，尚未支持 Tucker 和 block-term 分解（计划作为未来工作）。
- **生态扩展仍属未来计划**：对 PyTorch Geometric、AnnData、MuData 的原生支持尚未实现。
- **实际用例规模有限**：生物用例约 10⁴ 节点和 10⁵ 边，虽超出 muxViz 的分析极限，但相对于合成基准中的 10⁸–10⁹ 边规模仍有较大差距。
- **内存基线**：Python/PyTorch 导入固定约 0.4 GB，在极小网络上略逊于精简的 R 实现。
- **未报告 GPU 加速**：尽管基于 PyTorch，论文未展示利用 GPU 进行运算加速的实验。
